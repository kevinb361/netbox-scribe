# Requirements: NetBox Scribe

## Requirements

- [x] **REQ-001** — an installable `nbscribe` CLI exposes help and version output without requiring NetBox credentials (milestone: v0.1) (depends: none) (evidence: `tests/test_cli.py`; `make ci`; credential-free CLI smoke checks)
- [x] **REQ-002** — the client retrieves every page of synthetic NetBox device results and reports authentication, transport, and malformed-response failures without exposing the API token (milestone: v0.1) (depends: REQ-001) (evidence: `tests/test_client.py`; `make ci` with 13 tests)
- [x] **REQ-003** — `nbscribe export` normalizes device records into schema-versioned canonical YAML with stable ordering and byte-identical output for unchanged input (milestone: v0.1) (depends: REQ-002) (evidence: `tests/test_exporter.py` including deterministic unnamed-device identity; CLI canonical export tests; `make ci` with 32 tests)
- [x] **REQ-004** — an export is published atomically so a failed run cannot leave a partial snapshot or replace the last valid snapshot (milestone: v0.1) (depends: REQ-003) (evidence: `tests/test_exporter.py` covers per-file replacement, failed fetch, failed index publication, and index rollback after canonical failure; `make ci` with 32 tests)
- [x] **REQ-005** — every canonical snapshot validates against a published JSON Schema and incompatible schema versions fail clearly (milestone: v0.1) (depends: REQ-003) (evidence: packaged `src/netbox_scribe/schemas/v1/devices.schema.json`; validation/export/CLI tests including bounded non-UTF-8 handling; `make ci` with 33 tests)
- [x] **REQ-006** — the exporter generates a concise Markdown agent index that links canonical records and states source type, snapshot freshness, schema version, and exporter version (milestone: v0.1) (depends: REQ-003) (evidence: exact generated-index assertions in `tests/test_cli.py::test_export_command_writes_canonical_yaml`; `make ci` with 19 tests)
- [x] **REQ-007** — configuration supports explicit field and custom-field inclusion or exclusion, and synthetic tests prove denied values and credentials never appear in output or logs (milestone: v0.1) (depends: REQ-002) (evidence: policy and CLI end-to-end leak assertions in `tests/test_exporter.py` and `tests/test_cli.py`; `make ci` with 20 tests)
- [x] **REQ-008** — public-safe documentation and synthetic fixtures demonstrate installation, read-only NetBox token configuration, export, validation, Git usage, and agent/RAG consumption (milestone: v0.1) (depends: REQ-004, REQ-005, REQ-006, REQ-007) (evidence: `README.md`, `.env.example`, production-path-verified `examples/` artifacts, full public-doc/example safety scan, `make ci` with 33 tests)
- [x] **REQ-009** — HTTPS is required for credentialed NetBox requests unless the operator explicitly opts into insecure HTTP, and the 0.1.0 build is dogfooded and verified (milestone: v0.1.0) (depends: REQ-002, REQ-008) (evidence: client/CLI secure-default tests; default-rejection and explicit-override live dogfood against 11 devices; deterministic artifacts; packaged 0.1.0 wheel; `make ci` with 39 tests)
- [x] **REQ-010** — the complete Git history and public tree pass secret/privacy/license/trademark review with no private infrastructure disclosure (milestone: v0.1.1) (depends: REQ-009) (evidence: Gitleaks 8.30.1 full-history scan, bounded regex/history review, `pip-audit --strict`, dependency license inspection, tracked/ignored-file checks; intentional author email and obsolete local path disclosed in `docs/PUBLICATION.md`)
- [x] **REQ-011** — GitHub Actions runs the supported Python CI gate with least-privilege permissions and pinned major action versions (milestone: v0.1.1) (depends: REQ-010) (evidence: `.github/workflows/ci.yml`; current GitHub/Astral docs and signed release checks; full-SHA action pins; zizmor and YAML lint clean; Python 3.12 local matrix reproduction; `make ci`)
- [x] **REQ-012** — public contributor and security documentation explains support boundaries, vulnerability reporting, development checks, and the pre-alpha compatibility posture (milestone: v0.1.1) (depends: REQ-010) (evidence: `CONTRIBUTING.md`, `SECURITY.md`, README entry-point links and existing non-affiliation/pre-alpha guidance)
- [x] **REQ-013** — a final publication handoff names the exact GitHub repository settings and mirror/tag commands while retaining an explicit operator approval gate before any outward action (milestone: v0.1.1) (depends: REQ-010, REQ-011, REQ-012) (evidence: `docs/PUBLICATION.md`; no GitHub remote or public resource created)
- [x] **REQ-014** — `nbscribe export --view network` retrieves every page of device interfaces and IP addresses assigned to those interfaces without changing plain `nbscribe export` or weakening credential and pagination safety (milestone: v0.2) (depends: REQ-002, REQ-009) (evidence: generic same-origin `_list_records`; `tests/test_client.py::test_list_network_records_retrieves_each_relationship_resource`; `tests/test_cli.py::test_network_view_fetches_relationships_and_writes_canonical_document`; `make ci` with 41 tests)
- [x] **REQ-015** — the network view normalizes devices, interfaces, and assigned IP addresses into one schema-versioned canonical `network.yaml` with stable identities, ordering, and byte-identical output for unchanged input (milestone: v0.2) (depends: REQ-003, REQ-014) (evidence: packaged `network.schema.json`; view-aware validation; `tests/test_network_exporter.py::test_network_yaml_is_deterministic_and_valid_under_reordered_input`; `make ci` with 42 tests)
- [x] **REQ-016** — canonical network relationships use typed NetBox IDs and fail before publication when an interface-to-device or address-to-interface reference is dangling, ambiguous, or malformed (milestone: v0.2) (depends: REQ-015) (evidence: pre-render `_validate_network_relationships`; dangling/duplicate/preservation tests in `tests/test_network_exporter.py`; strict typed-reference schema; `make ci` with 45 tests)
- [x] **REQ-017** — the canonical network document and its derived relationship index publish as one recoverable atomic pair so a failure preserves the complete prior pair (milestone: v0.2) (depends: REQ-004, REQ-015, REQ-016) (evidence: network export reuses `_publish_snapshot_pair`; canonical-failure rollback test plus existing pair failure suite; CLI end-to-end index publication; `make ci` with 46 tests)
- [x] **REQ-018** — the relationship index provides bounded navigation from each device to its interfaces and assigned IP addresses while retaining provenance, freshness, schema version, exporter version, and a canonical `network.yaml` link (milestone: v0.2) (depends: REQ-006, REQ-016, REQ-017) (evidence: `render_network_index`; CLI end-to-end assertions for freshness, typed hierarchy, versions, and canonical link; deterministic canonical ordering; `make ci` with 46 tests)
- [x] **REQ-019** — interface and IP-address fields follow explicit per-resource inclusion/exclusion policy, and synthetic tests and public guidance prove denied values, credentials, and real inventory never enter published artifacts or logs (milestone: v0.2) (depends: REQ-007, REQ-008, REQ-018) (evidence: `NetworkExportPolicy`/`ResourcePolicy`; resource-specific CLI flags; deny-precedence leak test; README network guidance; production-generated synthetic interface/IP/network/index fixtures; `make ci` with 48 tests)
