## Verifier notes

Traceability is mechanical and is not a release gate on its own. Three things this table deliberately does
not resolve, all recorded as findings in `.planning/AUDIT.md` rather than as status downgrades:

1. **The entire v0.1.1 deliverable is uncommitted.** `.github/workflows/ci.yml`, `CONTRIBUTING.md`,
   `SECURITY.md`, and `docs/PUBLICATION.md` are untracked, and the `DESIGN.md` fix is a working-tree change.
   Every classification above is therefore a statement about the _working tree_. Running
   `docs/PUBLICATION.md`'s command block against `HEAD` today would publish a repository with no CI
   workflow, no security policy, no contributing guide, and the old `DESIGN.md`. See AUDIT.md **D3**.
2. **`docs/PUBLICATION.md` §1 understates the obsolete-path exposure** — it attributes the `/home/kevin`
   path to "the initial commit", but it is present in all five commits _including `HEAD`_
   (`DESIGN.md:6` and `DESIGN.md:64` at `a71831f`). See AUDIT.md **D1**.
3. **`README.md`'s Saga link is dead** — `https://github.com/earendil-works/saga` returns HTTP 404. See
   AUDIT.md **D2**.

Two methodological corrections to the prior pass, both of which changed the strength of the evidence rather
than the verdict. First, `pip-audit --strict` invoked bare audits whatever environment it happens to run in;
under an ephemeral runner that can be an environment containing none of this project's dependencies. Re-run
against an explicit 505-line frozen export, the result is genuinely clean. Second, "Gitleaks scanned the
tree" is not the same claim as "Gitleaks scanned the tree that would actually be published" — the scan here
was pointed at a materialized copy of `git ls-files ∪ git ls-files --others --exclude-standard`, so the
`.env`/`snapshot/`/`dist/` exclusions are demonstrated by construction rather than trusted from
`.gitignore`. Both re-runs are clean, which is the outcome that matters, but the earlier evidence would not
have distinguished clean from unexamined.

The strongest single piece of evidence for REQ-010 is not a scanner result. It is that the 11 real device
names and 2 real IP literals in the live dogfood snapshot were searched directly against both the public
tree and the full patch history and matched nothing — the scanners look for secret _shapes_, whereas this
looks for the specific private strings this repository has actually touched.
