## Verifier notes

The remediation is real and the tests behind it are load-bearing, which is the part that matters. I reverted
each of the three fixes in an isolated copy of the tree and confirmed the suite goes red at the expected
test every time — the origin-guard revert reds the protocol-relative parametrization and the malformed-URL
test, removing the HTTPS gate reds both secure-default tests, and returning the version to `0.1.0.dev0` reds
the version pin and the example byte-compare. A green suite here is evidence, not decoration.

The structural improvement is worth recording: the old guard reasoned about the *unresolved* candidate with
an `is_relative_url` short-circuit while `self._origin` came from the *resolved* base, and that mismatch was
the bug. The fix collapses both to one resolved-origin comparison and reuses the same resolved URL for the
actual request, so the URL that is checked and the URL that is fetched are the same object. That removes the
class of defect, not just the protocol-relative instance — which is why 24 hostile inputs, including several
the fix was never written against, all fail closed.

Traceability is mechanical and is not a release gate on its own. Two things this table does not capture, both
recorded in `.planning/AUDIT.md` rather than here: an off-origin redirect is correctly refused but reported
as `NetBox returned a malformed response`, which will misdescribe the common reverse-proxy redirect; and
`__version__` is derived from install metadata rather than a source literal, so the 0.1.0 pin is real but
indirect. Neither blocks the release.

Accuracy note, non-blocking and carried: the `make ci with N tests` counts embedded in the
REQ-002/005/006/007/008 evidence lines of `REQUIREMENTS.md` (13/33/19/20/33) are historical snapshots taken
when each requirement closed. The suite is now 39. Every named artifact still resolves, so no classification
changes.
